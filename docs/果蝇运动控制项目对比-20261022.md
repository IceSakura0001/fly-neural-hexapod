# 果蝇神经活动怎样驱动物理模型：检索与本机诊断

检索日期：2026-10-22。优先核对项目作者的论文、官方教程与源代码。结论是：目前本机实现验证了“神经活动能够改变关节目标”，没有验证“连接组自动产生步行”。两者不能等同。颤动不能作为已经实现运动控制的证据。

这几条路线说明：神经仿真与身体仿真之间的接口本身是研究对象。不能只把两个程序接在一起，就假定脑和身体已经匹配。

## 本机实测：颤动出在哪里

相同模型、质量、伺服参数和六边形站姿，先静站 10 s，再持续施加 forward 6 s，按 50 Hz 采样。原始数据见 `evidence/motion-diagnosis.json`。

| 指标 | MaleCNS 神经模式 | CPG 人工对照 |
|---|---:|---:|
| X 位移 | -0.0120 m | +0.6011 m |
| 具备明确卸载抬足条件的采样数（逐腿） | 0 / 0 / 0 / 0 / 0 / 0 | 80 / 84 / 80 / 80 / 80 / 80 |
| 足端球心最高高度 | 约 20–38 mm | 约 92–97 mm |
| 驱动力矩饱和比例 | 0 | 0 |
| 引擎警告 | 0 | 0 |

这里的“明确抬足”定义为该腿载荷小于单腿平均体重的 10%，且足端球心高于 40 mm；脚底球半径为 20 mm。这个工程阈值不表示不存在任何微小卸载或离地。-12 mm 的漂移不算可靠后退，更不算前进成功。

代码检查：当前 24,071 个细胞是 MaleCNS 下行/VNC 感觉运动子图，没有完整中央脑。将 220 个有肌肉注释的运动神经元汇成 36 个对抗肌群池，用平均放电差、固定增益、限幅与低通，转换成 18 路站姿附近的角度偏移。感觉编码也是工程假设，尚未标定为实际果蝇感受器的方向、关节调谐和相位关系。

**依据测量作出的判断：** 伺服有力矩，关节确有变化，但没有形成有效抬足与支撑交替；没有证据支持“增大扭矩就能走”。固定池平均还可能抵消重要的亚群时序。这是合理的机制假设，尚未通过逐项消融证明。质量约 107.63 kg、三自由度腿和果蝇肌骨系统差异很大，映射需要针对机器人重新校准。

## 对本项目适用的两条路线

1. **分层运动路线：** 选定并验证大脑/下行神经群，输出启停、左右运动驱动或速度/转向意图；由单独标记的身体控制器完成抬腿、支撑、足端反馈和 250 mm 高度控制。先用现有稳定物理基线检验脑输出的因果作用，再逐步替换低层模块。这接近 Eon / NeuroMechFly 的分工。它允许大脑调度运动，但不能称为全神经元直接控制每个关节。
2. **直接 VNC 运动路线：** 保留神经元到肌群接口，补足生理动力学和神经调制，标定分方向本体感觉反馈、肌群作用矩阵与身体尺度，验证能否自行形成协调节律；或训练受连接组约束的运动接口。工作量较大，结果不保证。若使用训练，必须报告哪些权重/增益经过拟合，不能再说只靠原始连接组自然会走。

建议优先建立分层路线作为可用闭环，同时保留当前神经直连作为科学对照。验收必须包含无刺激、切断选定脑输出、打乱输出身份及正常输出；若切断脑输出后身体仍按同样速度行走，就没有证明大脑控制运动。还应报告连续位移、航向误差、跌倒率、各腿支撑/摆动与力矩饱和，不能只看动画。

此次没有偷偷将神经模式替换成人工步态，也没有宣称已经解决神经步行。此次交付是检索对比、量化诊断、实时扭矩和可保存默认角度，为后续运动接口验证提供观测与调参能力。

## 新增界面怎样使用

控制台 `http://127.0.0.1:8765/` 的“当前关节扭矩”显示六腿各三个关节，共 18 路。大字显示绝对值，小字显示符号；单位 N·m。读取 MuJoCo `qfrc_actuator` 的对应关节自由度，包含伺服产生的驱动力矩，排除接触约束/被动力矩；不是 `ctrl` 目标角，也不是实机测量。传动比为 1，测试已核对与对应 `actuator_force` 一致。[MuJoCo 计算文档](https://mujoco.readthedocs.io/en/stable/computation/index.html#actuation-model)

右侧“默认关节角度”逐腿编辑髋、大腿、小腿的模型角度，点击“保存并复位”生效。复位和切换神经/CPG 模式沿用此参考；承重与高度补偿会使实际角度与初值有所差异。当前验证范围为相对六边形预设 ±15°，足端初始高度极差不超过 30 mm，球心距理想接地高度偏差不超过 40 mm，并检查逆解可达性。不是实机机械关节极限。

自定义角度会改变足端布置，界面会标为“自定义”，不再声称保持正六边形；250 mm 净空仍作为高度闭环目标。可随时点“恢复六边形预设”。配置保存在本机 Docker 命名卷 `hexapod-neuro_stance-settings`，常规容器重启/重建保留。`docker compose down -v` 会删除该卷，请不要将其当普通停止命令使用。
